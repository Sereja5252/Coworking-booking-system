# Система бронирования для коворкинга

Проект реляционной базы данных для управления бронированиями переговорных комнат, рабочих мест и оборудования. Основной упор сделан на реализации бизнес-логики на уровне самой СУБД с помощью триггеров и хранимых процедур.

## Стек технологий
* **База данных:** PostgreSQL
* **Скрипты и логика:** SQL, PL/pgSQL

## Ключевой функционал и архитектура

* **Защита от двойного бронирования:** Реализован триггер `check_busy`, который перед вставкой или обновлением записи автоматически проверяет отсутствие пересечений по времени для конкретного ресурса.
* **Версионирование тарифов:** Система хранит полную историю изменения цен (через таблицу `TARIFF` и флаги активности `is_active`). Это гарантирует корректный расчет стоимости для любых исторических бронирований.
* **Автоматический расчёт чека:** При добавлении брони срабатывает триггер `calc_total`, который с помощью функций (например, `get_hours`) вычисляет длительность аренды и итоговую сумму по актуальному тарифу.
* **Оптимизация:** Созданы частичные индексы (например, для ускорения поиска неоплаченных броней в статусе `pending`).

## Структура БД
Спроектирована физическая модель со строгим соблюдением нормальных форм и ссылочной целостности (Primary/Foreign Keys). Основные сущности:
* `CLIENT` — данные пользователей.
* `RESOURCE` — доступные объекты коворкинга.
* `TARIFF` — справочник тарифов с историчностью.
* `BOOKING` — реестр бронирований.
* `PAYMENT` — транзакции и статусы оплат.
